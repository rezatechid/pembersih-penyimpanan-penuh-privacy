1. About the app

Indonesian name: Pembersih Penyimpanan Penuh. English name: Storage Cleaner & File Tools.

Developer: reza tech.

Effective date: 29 October 2026.

The app helps you view usage of the Android internal data partition, clean certain temporary files owned by this app, and manage files you choose through the Android document picker. It does not scan all storage on your device or promise to clean every app’s cache.

2. Information processed

Information · Purpose and processing

Total, available and used space on the internal data partition
Read through StatFs for display. This is not a guarantee of the device’s total physical capacity and does not require reading all files.
Chosen file URI, name, size, MIME type, availability and deletion capability
Obtained from the Android document provider to display, sort and validate files you chose. Unknown sizes remain unknown. File names may contain personal information.
Checkboxes, deletion status/results and locks on unverified results
Kept in session memory to carry out your choices, report results and prevent deletion retries for the same URI during that session.
Metadata of eligible temporary files owned by the app
Used to validate safe cleaning and count bytes of files actually deleted within the automatic cleaner’s limited scope.
Appearance preferences
Code uses private local DataStore appearance, with key theme_mode for system/light/dark. The current app reads this preference; it does not provide a separate theme settings page.

To compare sizes, the chosen-file feature reads metadata without opening or copying file contents for analysis. The audited version has no accounts, login, ads, analytics or crash-report upload to a developer server.

3. File access and deletion confirmation

Selection uses the official Android Storage Access Framework (SAF). You choose the files the app may inspect, up to 50 unique URIs per selection. Files are not automatically checked for deletion.

Choosing a file alone does not delete it. You must check the file and confirm deletion in the app. A provider may ask for additional Android approval. The app requests deletion through the official document provider API. Deletion may be permanent depending on the provider; this app does not provide file recovery.

If the result cannot be verified, it is not counted as confirmed success or failure, and its size is excluded from confirmed deleted bytes. Deletion of the same URI is disabled while the session ViewModel is alive. Check the file manually in the Files app before trying again in a later session. Ending the app process clears session reports and locks but does not reverse deletions that already happened.

The app does not access other apps’ private caches or use root, an Accessibility Service, or all-files access permission. Automatic cleaning covers only eligible safe temporary files owned by this app. It does not scan or delete your photos, videos, documents, music or Downloads. If you explicitly choose and confirm a personal file through SAF, the deletion request targets that selected file.

4. Transmission and sharing

Based on the code, configuration and runtime dependencies audited for this version, the app does not upload chosen-file metadata or contents, storage statistics or preferences to developer servers or advertising/analytics services. No app backend or INTERNET permission was found in the audited configuration.

Metadata and deletion requests are sent through Android to the document provider you choose. A provider may represent local storage or a third-party cloud service. Cloud providers may use a network connection and process requests under their own policies. This is not a promise that every provider or Android operation is offline. This app does not control third-party cloud services, backups or Android system logs.

MANAGE ANDROID STORAGE opens Android settings. You manage other apps’ caches manually there.

5. Local storage, retention and deletion

File lists, metadata, checkboxes, reports and deletion locks are held in ViewModel memory. Rotation can preserve the session. Replacing a selection or ending the session/process can replace or clear information. The app does not maintain a permanent chosen-file history or deletion ledger, or call takePersistableUriPermission to retain SAF access. Permissions and records managed by Android/providers follow those systems; we do not promise a fixed permission lifetime.

Stored appearance preferences remain in private app storage until changed by supporting code or until private app data is removed. You can clear app data or uninstall the app through Android settings to remove private local app data. This does not restore files already deleted or delete unrelated personal files outside private app data.

Android may clear temporary cache. The app’s cleaning button removes only eligible files within its safe scope, not all cache or app preferences.

The manifest sets allowBackup=false. Some devices may nevertheless transfer app data during device-to-device migration. No specific dataExtractionRules are configured, and migration has not been tested, so we do not promise to prevent every system/OEM transfer.

6. Security and your choices

Preferences use Android’s private app sandbox. The app rechecks metadata before deleting a selected file. Automatic cleaning restricts directory/file names and rejects unsafe symbolic links. Audited production code does not log file names or URIs; Android/providers may generate their own system logs.

You may cancel the document picker or confirmation dialog. Returning from Settings does not automatically delete chosen files. Failed/unverified items are not replaced by deleting other files. No specific increase in free space is guaranteed; cloud metadata and delayed statistics can affect reported results.

7. Contact and policy changes

For privacy questions or support contact reza tech at rezatech.id@gmail.com. Contact is optional through your email service; the app does not send email or attach data automatically. Messages you choose to send may contain your email address and message contents, processed by the email services involved. Avoid sending private files, URIs or sensitive logs unless necessary and after removing personal information.

Changes to data handling must be reflected in this policy and the Data safety information.

8. Privacy of GitHub Pages visitors

These static pages contain no trackers or analytics. When a page is hosted on GitHub Pages and visited, GitHub logs and stores visitors' IP addresses for security, even without GitHub sign-in.

Hosting-data handling follows the GitHub Privacy Statement. This does not mean that the app uploads your chosen files to GitHub.
